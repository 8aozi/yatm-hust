# 详细使用指南

默认启动入口已集成“从微信链接提取 openId → 接入签到 → 失效后等待新链接”。已保存西十二教学楼、计算机大楼和东九教学楼的近似中心坐标。

1. macOS 双击 `01-macos/start.command`，Windows 双击 `02-windows/start.cmd`，或在项目目录执行 `npm start`。
2. 启动时按编号选择本次定位，回车沿用上次选择；输入 M 可管理预设，Q 退出。已保留西十二教学楼（纬度 `30.511196`、经度 `114.401579`，WGS-84）作为第一个预设。
3. 在电脑微信「微助教服务号」中打开「学生 → 签到」，从微信页面复制带 `openid=` 参数的完整链接。将完整 URL 或裸 openId 粘贴到运行终端并按回车，程序才会提取、验证凭据并继续签到，无需运行单独的获取工具。获取方法详见 [获取微信链接](AcquireOpenID.md)；普通页面链接可能不含这个参数。
4. 普通签到、GPS 签到会由原项目逻辑自动提交。检测到二维码签到后，终端会显示二维码，需要你使用微信扫描。脚本运行期间电脑需要保持联网和唤醒。
5. 扫码后或登录失效时，重新在微信中打开签到页，复制新链接后粘贴到终端并回车，无需重启。按 Control+C 停止程序。

登录凭据只需在本机处理，无需发到聊天里；身份验证成功后，程序在终端直接显示姓名和完整 openId；读取与验证过程不显示中间提示。坐标保存在 Git 忽略的 `config.json` 中。每次启动都需在终端粘贴凭据并回车；凭据仅在当前进程内存中使用，不自动保存或恢复。系统剪贴板不再被程序监听或读取，旧 `OPEN_ID`、`clipboard.paste`、`devtools` 设置不再作为登录来源。

## macOS 与 Windows

文件名已统一为英文，界面提示仍为中文。

| 用途 | macOS | Windows |
| --- | --- | --- |
| 集成启动 | `01-macos/start.command` | `02-windows/start.cmd` |
| 管理地点 | `01-macos/manage-locations.command` | `02-windows/manage-locations.cmd` |

Mac 通常使用 Command+V，Windows 通常使用 Ctrl+V 或右键，将链接粘贴到终端后按回车。两端使用相同的终端输入逻辑，不依赖 PowerShell 读取剪贴板。

本次已在 macOS 编译并运行离线测试，终端输入已做离线验证，尚未在 Windows 实机及真实微助教签到流程验证。二维码扫码仍由微信完成，自动授权仍无已验证方案。

## 多地点预设

macOS 双击 `01-macos/manage-locations.command`、Windows 双击 `02-windows/manage-locations.cmd`，或在项目目录运行 `npm run configure`，可以新增、修改、删除地点，也可以设置默认地点。每个地点填写名称、纬度、经度；名称不能重复，至少保留一个地点。管理操作完成后立即保存，选择 0 返回。修改时直接回车保留原值。

每次启动都会显示地点列表，输入编号使用对应坐标，并记住这次选择。选中的地点会同步写入 `config.json` 的 `lat`、`lon`，供当前签到进程使用。所有地点存于同一文件的 `locations`，默认地点名称存于 `selectedLocation`。

运行过程中修改预设不会改变已经启动的进程；切换地点请按 Control+C 停止，再重新启动选择。选择地点也可以通过环境变量 `YATM_LOCATION` 显式指定地点（macOS：`YATM_LOCATION="西十二教学楼" npm start`；Windows PowerShell：`$env:YATM_LOCATION="西十二教学楼"; npm start`）；没有交互终端且未指定名称时沿用上次选择。名称不存在会停止启动，避免误用其他地点。登录阶段仍需交互终端粘贴凭据。

## 用户侧如何区分签到类型

GPS 签到就是定位签到。程序依据微助教接口的 `isGPS` 和 `isQR` 标记判断，终端和通知会显示类型：

- 普通签到：不附带定位坐标。
- 定位签到（GPS）：显示选中的地点及经纬度，并随签到请求提交。
- 扫码签到：显示二维码，需通过微信扫码。
- 扫码 + 定位签到：两个标记同时开启时，仍进入微信扫码流程；本地预设坐标不会传入这个流程，定位由微信页面处理，具体行为须实际验证。

## 可选入口（通常只需默认启动入口）

### 只获取，不签到

macOS 双击 `01-macos/get-openid.command`、Windows 双击 `02-windows/get-openid.cmd`，或运行 `npm run openid`。复制微信签到 URL 后，粘贴到工具终端并按回车。工具显示提取出的完整 openId，并注明尚未验证有效性；不写入文件、不访问网络、不签到，也不自动读写剪贴板。需要使用输出时，从终端复制 openId。

### 获取范围

主程序和获取工具均接受完整的 `https://v18.teachermate.cn/` 链接（含唯一的 openid 查询参数）或完整的 32 位十六进制 openId。格式不正确时提示重新粘贴。程序不会自行打开微信页面或生成授权凭据；请按[获取微信链接](AcquireOpenID.md)的方法取得含参数的链接。

`npm run start:manual` 保留为 `npm start` 的别名；旧的 `start-clipboard` 命令和启动文件已移除。

## 终端状态与错误处理

终端每条状态带时间和中文标签。读取和验证过程不显示中间提示；通过学生身份查询并取得姓名后，直接显示“openId 验证通过”、姓名和完整 openId。失败或超时才显示相应错误。凭据值本身不能说明是否过期。

- `等待粘贴输入`：提示一次操作和 `URL / openId:` 后静默等待。必须将 URL 或 openId 粘贴到终端并按回车；只复制链接不会触发验证。
- `openId 验证通过` / `运行正常`：身份查询通过并继续监测。没有签到或已经处理完当前签到属于正常状态。
- `临时故障｜自动重试`：网络超时、中断，HTTP 408 / 425 / 429 或 5xx，以及二维码连接断开等。保留当前凭据，失败后默认等待 5 秒再重试，独立于正常查询签到的轮询间隔；若 HTTP Retry-After 要求等待更久，则遵守服务指定时间。连续失败 3 次起提示检查网络等选项。
- `openId 已失效或被拒绝`：身份请求返回 HTTP 401 或明确的登录失效信息。停用旧凭据，回到等待粘贴新 URL 并回车，不要求重启。
- `需要操作`：配置、输入格式或不确定的接口错误。输入格式问题继续等待输入；无法恢复的错误明确标记“程序已停止 / 未启动”，列出处理办法并用 `or` 分隔，不会把所有异常一概称为过期。

默认网络请求超时为 15 秒。`request-timeout` 表示程序已接收粘贴的凭据，但向微助教发出的某个网络请求超过 15 秒仍未完成；随后等待 5 秒重试，不表示 ID 已失效。403、未知业务错误、学生身份缺失或非 JSON 响应不能单凭现象判断 openId 失效，因此会显示操作建议。临时故障也可能持续存在，应根据多次重试后的提示检查网络或服务状态。

完整的操作时间线及状态对照表见[项目主页](../README.md)。

## 主动替换凭据与打开页面的顺序

运行终端随时接受粘贴：把完整 URL 或裸 openId 粘贴进去，按回车即触发验证。无需先输入 `I` 或其他切换命令。验证成功显示姓名与 openId；未识别出有效格式的普通文字不会替换当前会话。

`R + 回车` 会暂停后续签到并返回等待粘贴输入。此时粘贴同一凭据或新凭据并回车均可。`Q + 回车` 或 `Control+C` 退出。切换会取消本地网络请求和等待，关闭旧二维码订阅，并忽略旧响应；已经发送到服务器的请求无法撤回。启动需要交互终端，后台无终端运行会提示操作建议并退出。

先打开微信签到页、再启动脚本也可以。脚本不记录微信页面打开时间，只检查粘贴后提交的文本。页面跳转后 URL 可能不再含 openid 参数；凭据也可能被服务拒绝，应根据终端提示处理。

正常监测、验证或网络重试时都可以直接粘贴新凭据并回车。主动更换不同凭据或按 R 会清空本机已处理签到的记录；直接粘贴同一凭据只重新验证，保留已处理记录。

## 已知限制

- “无需外部帮助”是指按项目设计无需同学转发二维码，不代表无需微信、微助教服务或手动操作。
- macOS 全自动扫码和自动刷新 openId 没有上游支持方案。默认采用手动微信扫码。
- 华科校内版支持仍是未关闭的问题：https://github.com/ManiaciaChao/yatm/issues/8 。如果你使用的是校内版，不能把本项目安装完成当作可用性验证。
- 编译和本地启动检查不能证明当前微助教接口可用；实际签到仍需有效账号和正在进行的签到才能验证。
- GPS 使用固定配置坐标，不会自动跟随你移动。当前坐标是西十二楼轮廓外接矩形的中心估算，不是某个教室的实测值；原项目未明确接口要求的坐标系，仍需现场验证。
