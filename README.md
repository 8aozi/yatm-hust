## 实现逻辑
粘贴微信签到页链接（含身份识别openid） -> 粘贴到终端 -> 自动验证身份并查询签到类型 ->
- 普通签到、定位签：由程序提交；
- 二维码签到：显示QRcode，～～请自便～～；

## 1. 首次安装
>已安装直接跳 「2.日常启动」

1. 安装 [Node.js 22 或 24 LTS](https://nodejs.org/)，安装并登录电脑微信。
2. 双击 `setup` 文件，等待显示 `Setup complete`；报错时按提示处理后重试。


## 2. 日常启动

1. 双击 `start` 文件
2. 选择地点：输入地点编号并回车。直接回车沿用上次选择；没有预设时按提示创建。
3. 复制链接：在电脑微信打开「微助教服务号 → 学生 → 签到」，复制带 `openid` 参数的页面链接（[获取方法](docs/AcquireOpenID.md)）。
4. 终端输入：粘贴完整链接（含 32 位 openId），**回车**。验证成功后显示姓名和完整 ID，开始查询签到。
5. 验证中：静默查询，仅失败或超时才报错 。

### 终端状态

| 状态 | 含义 | 需要的操作 |
| --- | --- | --- |
| 等待粘贴输入 | 尚未提交凭据，程序正在等待输入 | 粘贴 URL 或 openId 并回车； |
| openId 验证通过 | 微助教已确认本次身份，终端显示姓名和 ID | 保持运行；不代表 ID 永久有效 |
| 运行正常 | 正在查询，暂无新签到或当前签到已处理 | 保持电脑联网和唤醒 |
| 等待微信扫码 | 正在获取二维码或等待扫描 | 二维码出现后，请自便（） |
| 签到完成 | 已收到提交成功、已签到或扫码完成结果 | 自检是否成功； |
| 临时故障｜自动重试 | 已接收凭据，但请求暂时失败。`request-timeout` ：向微助教发出的某个网络请求超过 15 秒仍未完成，不表示 ID 已失效 | 程序自动执行：保留当前 ID，失败后等 5 秒自动重试；连续失败时检查网络或代理，～～或者直接重开吧～～  |
| openId 已失效或被拒绝 | 身份接口明确拒绝当前凭据 | 自行获取新的微信 URL，重新尝试 |
| 需要操作 | 输入、配置或无法确定原因的接口错误 | 可按提示处理（`or` 表示可选办法）；～～但不如直接重开～～ |

### 运行中操作

- **粘贴 URL / openId + 回车**：直接替换或重新验证凭据，网络重试期间也可使用。
- **R + 回车**：暂停后续动作，等待重新粘贴。
- **Q + 回车 / Control+C**：退出。

## 3. 增改定位

双击 `manage-locations` 文件，按菜单新增、修改、删除或设为默认，输入 `0` 返回。修改立即保存到 `config.json`；下次启动选择地点后生效。运行中换地点需先退出再启动。

本机预设：**1 西十二教学楼 · 2 计算机大楼 · 3 东九教学楼**。

～～免责声明～～：GPS 即定位签到，使用所选预设；预设为建筑近似坐标，精度和范围不保真，见[坐标说明](docs/usage.md#新增地点坐标2026-11-11)。

## 4. 其他功能

- **只提取 ID**：双击 `get-openid`，粘贴 URL 并回车，工具显示 ID；是独立的小功能，日常启动无需运行它。
- **命令行启动**：在项目根目录运行 `npm start`。
- **修改源码后**：运行 `npm run build` 更新运行文件；`npm test` 执行离线测试。
